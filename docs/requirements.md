## 用語定義

| 用語               | 定義                                                           |
| ------------------ | -------------------------------------------------------------- |
| カンバンボード     | タスクをカードで管理し、複数の列（カラム）で状態を視覚化するボード |
| カラム             | ボード上の縦列。タスクの進捗状態を表す（未着手・作業中・完了）  |
| カード             | 1つのタスクを表すUI要素                                        |
| モーダル           | 画面上に重ねて表示するダイアログウィンドウ                     |
| MVP                | Minimum Viable Product。最小限の機能で動作する最初のリリース版 |

## 1. プロジェクト概要

### 1-1. 目的

Trello風のカンバンボード形式によるタスク管理WebAppを開発する。個人の日常タスクを視覚的に管理し、作業進捗を直感的に把握できるツールを作成する。

### 1-2. 背景・動機

スクールの講義の一環としてWebアプリの開発に取り組む。同時に、自身の日常タスク管理にも実際に使用することを目指す。

### 1-3. 成果物

- ブラウザで動作するHTML/CSS/JavaScript製のWebアプリ（サーバー不要）
- 本要件定義書

## 2. 利用者・利用環境

### 2-1. 対象ユーザー

開発者自身（個人利用）。日常のタスク・学習・作業の進捗を自分で管理するために使用する。

### 2-2. 利用環境

| 項目         | 内容                                   |
| ------------ | -------------------------------------- |
| デバイス     | PC（メイン）                           |
| ブラウザ     | Google Chrome 120 以降                 |
| JavaScript   | 有効であること                         |
| ネットワーク | インターネット接続不要（ローカル動作） |

## 3. 機能要件

機能要件とは「システムが何をするか」の定義である。以下は本アプリが必ず満たすべき機能を定義する。

### 3-1. カラム（列）管理

- 「未着手」「作業中」「完了」の3列を固定で表示する
- 各列のカード数をリアルタイムで表示する

### 3-2. カード（タスク）管理

- カードを任意の列に新規作成できる
- 作成済みのカードを編集（内容修正）できる
- カードを削除できる
- カードを列間で移動できる（ドラッグ＆ドロップまたはボタン）

### 3-3. 入力項目定義

カード作成・編集時に入力できる項目は以下のとおり。

| 項目     | 必須 / 任意 | 内容                        | バリデーション                   |
| -------- | ----------- | --------------------------- | -------------------------------- |
| タイトル | 必須        | タスク名（テキスト）        | 空文字不可・最大100文字          |
| 説明文   | 任意        | 詳細メモ（複数行可）        | 最大500文字                      |
| 優先度   | 任意        | 高 / 中 / 低 の3段階        | 未選択の場合は「中」をデフォルト |
| 期限     | 任意        | 日付指定                    | 過去日付も入力可能               |

### 3-4. 期限の表示ルール

期限の状態を色で視覚的に伝える。

| 状態     | 表示           | 色       |
| -------- | -------------- | -------- |
| 期限超過 | 期限超過 MM/DD | 赤       |
| 期限当日 | 今日           | オレンジ |
| 3日以内  | 📅 MM/DD       | 黄       |
| 4日以降  | 📅 MM/DD       | グレー   |

### 3-5. データ保存

- カードの追加・編集・削除・移動をブラウザのローカルストレージに自動保存する
- ブラウザを閉じ・再起動してもデータが消えない

## 4. 非機能要件

非機能要件とは「システムがどのように動くか」の品質基準である。

### 4-1. パフォーマンス

| 項目             | 基準                                              |
| ---------------- | ------------------------------------------------- |
| 動作保証カード数 | 合計100枚まで（各列33枚程度）                     |
| 画面反映速度     | カード追加・移動・削除の操作から300ms以内に反映   |
| 初回読み込み     | ファイルを開いてから2秒以内にボードを表示         |

### 4-2. 対応環境

| 項目         | 内容                                          |
| ------------ | --------------------------------------------- |
| 対応ブラウザ | Google Chrome 120 以降                        |
| 非対応環境   | Internet Explorer・Safari・Firefox は対象外   |
| 画面解像度   | 横幅 1280px 以上のデスクトップ画面            |

### 4-3. データ保持

- ブラウザのタブを閉じてもデータが保持される（ローカルストレージ）
- ブラウザのキャッシュクリア・シークレットモードではデータが消える可能性があることを許容する

### 4-4. エラー処理

| エラー状況                     | アプリの挙動                                     |
| ------------------------------ | ------------------------------------------------ |
| タイトル未入力での保存         | 「タイトルを入力してください」と表示し保存しない |
| ローカルストレージ保存失敗     | 「保存に失敗しました」とアラート表示             |
| ローカルストレージ読み込み失敗 | 空のボードで起動し、エラーをコンソールに出力     |

### 4-5. アクセシビリティ

- Esc キーでモーダルを閉じられること
- ボタン・入力欄がキーボードでフォーカス可能であること

## 5. 画面設計

### 5-1. 画面一覧

本アプリの画面は全て1画面（アプリが1ページで完結する構成）。

| 画面               | 概要                                     |
| ------------------ | ---------------------------------------- |
| メイン画面         | ボード（カラム＋カード）の表示           |
| カード作成モーダル | カード一覧の上に重ね表示（投影）         |
| カード編集モーダル | カード一覧の上に重ね表示（投影）         |

### 5-2. 画面遷移図

```
メイン画面
  │
  ├─ [+追加] クリック ──→ カード作成モーダル
  │                              │
  │                    [保存] ──→ メイン画面（カード追加）
  │                    [キャンセル / Esc] ──→ メイン画面
  │
  └─ カードの[編集] クリック ──→ カード編集モーダル
                                       │
                             [保存] ──→ メイン画面（カード更新）
                             [キャンセル / Esc] ──→ メイン画面
```

## 6. データ設計

### 6-1. カードデータ項目定義

ローカルストレージに保存するデータの構造を定義する。

| フィールド名 | 型     | 必須 | 説明                              |
| ------------ | ------ | ---- | --------------------------------- |
| id           | 文字列 | 必須 | カード一意識別子（ランダム生成）  |
| title        | 文字列 | 必須 | タスク名                          |
| desc         | 文字列 | 任意 | 説明文（空文字も可）              |
| priority     | 文字列 | 必須 | `high` / `mid` / `low` のいずれか |
| due          | 文字列 | 任意 | `YYYY-MM-DD` 形式（空文字も可）   |

### 6-2. ストレージ構造

データは列ごとにカードの配列として保存する。

```json
{
  "todo":  [ { "id": "...", "title": "...", "desc": "", "priority": "mid", "due": "" } ],
  "doing": [ { "id": "...", "title": "...", "desc": "", "priority": "high", "due": "2026-12-31" } ],
  "done":  [ { "id": "...", "title": "...", "desc": "", "priority": "low", "due": "" } ]
}
```

## 7. 開発スコープ

### 7-1. MVP（初期リリースで実装する機能）

最初から全機能を目指すのではなく、動くものを早期に完成させることを優先する。

- 3列のカンバンを画面に表示する
- カードの新規作成（タイトルのみ）
- カードの削除
- ボタン操作による列間移動

### 7-2. MVP後に追加する機能

- 説明文・優先度・期限の入力
- カードの編集機能
- ドラッグ＆ドロップによる列間移動
- ローカルストレージへの自動保存

### 7-3. スコープ外（今回は作らないもの）

- ユーザー登録・ログイン機能
- 複数ユーザーでの共有・協同作業
- カラムの追加・削除
- サーバーへのデータ保存

## 8. 受け入れ条件

受け入れ条件とは「この機能が正しく完成したと判断する基準」である。検収時に以下の確認を行う。

### 8-1. カード作成

| # | 確認内容                                                               | 合否 |
| - | ---------------------------------------------------------------------- | ---- |
| 1 | タイトルを入力して保存すると、対象カラムにカードが追加される           |      |
| 2 | タイトルを空のまま保存しようとすると、エラーメッセージが表示され保存されない |      |
| 3 | ページを再読み込みしても追加したカードが表示される                     |      |

### 8-2. カード編集

| # | 確認内容                                                       | 合否 |
| - | -------------------------------------------------------------- | ---- |
| 1 | 編集ボタンを押すと、既存の内容が入力済みのモーダルが開く       |      |
| 2 | 内容を変更して保存すると、カードの表示が更新される             |      |

### 8-3. カード削除

| # | 確認内容                                                       | 合否 |
| - | -------------------------------------------------------------- | ---- |
| 1 | 削除ボタンを押すとカードがボードから消える                     |      |
| 2 | ページを再読み込みしても削除したカードは表示されない           |      |

### 8-4. カード移動

| # | 確認内容                                                       | 合否 |
| - | -------------------------------------------------------------- | ---- |
| 1 | 移動ボタンを押すと、カードが隣のカラムに移動する               |      |
| 2 | 各カラムのカード数表示がリアルタイムで更新される               |      |

### 8-5. 期限表示

| # | 確認内容                                                           | 合否 |
| - | ------------------------------------------------------------------ | ---- |
| 1 | 期限が過去日付のカードは赤色で「期限超過」と表示される             |      |
| 2 | 期限が当日のカードはオレンジで「今日」と表示される                 |      |

## 9. 前提条件・制約・リスク

### 9-1. 前提条件

- 利用者の端末に Google Chrome 120 以降がインストールされていること
- ブラウザの JavaScript が有効になっていること
- ブラウザのローカルストレージが有効になっていること

### 9-2. 制約条件

| 制約                       | 内容                                                 |
| -------------------------- | ---------------------------------------------------- |
| サーバーなし               | バックエンドを持たないため、複数端末での同期は対象外 |
| ローカルストレージ容量制限 | 通常 5MB が上限。大量データの登録は動作保証対象外    |
| 単一ユーザー               | 認証機能を持たず、複数人での利用は対象外             |

### 9-3. リスクと対策

| リスク                             | 影響度 | 対策                                            |
| ---------------------------------- | ------ | ----------------------------------------------- |
| キャッシュクリアによるデータ消失   | 高     | ユーザーへの注意喚起（アプリ内に説明文を表示）  |
| シークレットモードでのデータ非保持 | 中     | 通常モードでの使用を推奨する旨を記載            |
| ブラウザ更新による動作変化         | 低     | 動作確認済みバージョンを本書に明記              |
