# タスク管理アプリ 要件定義書

## 1. プロジェクト概要

### 1-1. 目的

Trello風のカンバンボード形式によるタスク管理WebAppを開発する。個人の日常タスクを視覚的に管理し、作業進捗を直感的に把握できるツールを作成する。

### 1-2. 背景・動機

スクールの講義の一環としてWebアプリの開発に取り組む。同時に、自身の日常タスク管理にも実際に使用することを目指す。

### 1-3. 成果物

- ブラウザで動作するHTML/CSS/JavaScript製のWebアプリ（サーバー不要）
- 本要件定義書

---

## 2. 利用者・利用環境

### 2-1. 対象ユーザー

開発者自身（個人利用）。日常のタスク・学習・作業の進捗を自分で管理するために使用する。

### 2-2. 利用環境

- デバイス：PC（メイン）
- ブラウザ：Google Chrome
- ネットワーク：インターネット接続不要（ローカル動作）

---

## 3. 機能要件

機能要件とは「システムが何をするか」の定義である。以下は本アプリが必ず満たすべき機能を定義する。

### 3-1. カラム（列）管理

- 「未着手」「作業中」「完了」の3列を固定で表示する
- 各列のカード数をリアルタイムで表示する

### 3-2. カード（タスク）管理

- カードを任意の列に新規作成できる
- 作成済みのカードを編集（内容修正）できる
- カードを削除できる
- カードを列間で移動できる（ドラッグ＆ドロップまたはボタン）

### 3-3. 入力項目定義

カード作成・編集時に入力できる項目は以下のとおり。

| 項目       | 必須 / 任意 | 内容                        |
| ---------- | ----------- | --------------------------- |
| タイトル   | 必須        | タスク名（テキスト）        |
| 説明文     | 任意        | 詳細メモ（複数行可）        |
| 優先度     | 任意        | 高 / 中 / 低 の3段階        |
| 期限       | 任意        | 日付指定                    |

### 3-4. 期限の表示ルール

期限の状態を色で視覚的に伝える。

| 状態       | 表示              | 色         |
| ---------- | ----------------- | ---------- |
| 期限超過   | 期限超過 MM/DD    | 赤         |
| 期限当日   | 今日              | オレンジ   |
| 3日以内    | 📅 MM/DD          | 黄         |
| 4日以降    | 📅 MM/DD          | グレー     |

### 3-5. データ保存

- カードの追加・編集・削除・移動をブラウザのローカルストレージに自動保存する
- ブラウザを閉じ・再起動してもデータが消えない

---

## 4. 非機能要件

非機能要件とは「システムがどのように動くか」の品質基準である。今回は個人利用のため、最低限の定義とする。

- ブラウザのタブを閉じてもデータが保持される（ローカルストレージ）
- PCブラウザ上で支障なく動作する

---

## 5. 画面設計

### 5-1. 画面一覧

本アプリの画面は全で1画面（アプリが1ページで完結する構成）。

| 画面               | 概要                                     |
| ------------------ | ---------------------------------------- |
| メイン画面         | ボード（カラム＋カード）の表示           |
| カード作成モーダル | カード一覧の上に重ね表示（投影）         |
| カード編集モーダル | カード一覧の上に重ね表示（投影）         |

### 5-2. レイアウト構成

- **ヘッダーエリア**：アプリ名、総タスク数の表示
- **ボードエリア**：3列のカンバン（各列＝列ヘッダー＋カード一覧＋追加ボタン）
- **カード**：優先度バッジ、タイトル、説明文（あれば）、期限（あれば）を表示
- **モーダル**：カード作成・編集用のダイアログ

---

## 6. データ設計

### 6-1. カードデータ項目定義

ローカルストレージに保存するデータの構造を定義する。

| フィールド名 | 型       | 必須 | 説明                                  |
| ------------ | -------- | ---- | ------------------------------------- |
| id           | 文字列   | 必須 | カード一意識別子（ランダム生成）      |
| title        | 文字列   | 必須 | タスク名                              |
| desc         | 文字列   | 任意 | 説明文（空文字も可）                  |
| priority     | 文字列   | 必須 | `high` / `mid` / `low` のいずれか     |
| due          | 文字列   | 任意 | `YYYY-MM-DD` 形式（空文字も可）       |

### 6-2. ストレージ構造

データは列ごとにカードの配列として保存する。

```json
{
  "todo":  [ { "id": "...", "title": "...", "desc": "", "priority": "mid", "due": "" } ],
  "doing": [ { "id": "...", "title": "...", "desc": "", "priority": "high", "due": "2024-12-31" } ],
  "done":  [ { "id": "...", "title": "...", "desc": "", "priority": "low", "due": "" } ]
}
```

---

## 7. 開発スコープ

### 7-1. MVP（初期リリースで実装する機能）

最初から全機能を目指すのではなく、動くものを早期に完成させることを優先する。

- 3列のカンバンを画面に表示する
- カードの新規作成（タイトルのみ）
- カードの削除
- ボタン操作による列間移動

### 7-2. MVP後に追加する機能

- 説明文・優先度・期限の入力
- カードの編集機能
- ドラッグ＆ドロップによる列間移動
- ローカルストレージへの自動保存

### 7-3. スコープ外（今回は作らないもの）

- ユーザー登録・ログイン機能
- 複数ユーザーでの共有・協同作業
- カラムの追加・削除
- サーバーへのデータ保存
