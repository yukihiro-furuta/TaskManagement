## 用語定義

| 用語               | 定義                                                               |
| ------------------ | ------------------------------------------------------------------ |
| カンバンボード     | タスクをカードで管理し、複数の列（カラム）で状態を視覚化するボード |
| カラム             | ボード上の縦列。タスクの進捗状態を表す（未着手・作業中・完了）     |
| カード             | 1つのタスクを表すUI要素                                            |
| モーダル           | 画面上に重ねて表示するダイアログウィンドウ                         |
| MVP                | Minimum Viable Product。最小限の機能で動作する最初のリリース版     |
| ローカルストレージ | ブラウザが提供するクライアントサイドのデータ保存領域               |

## 1. プロジェクト概要

### 1-1. 目的

Trello風のカンバンボード形式によるタスク管理WebAppを開発する。個人の日常タスクを視覚的に管理し、作業進捗を直感的に把握できるツールを作成する。

### 1-2. 背景・動機

スクールの講義の一環としてWebアプリの開発に取り組む。同時に、自身の日常タスク管理にも実際に使用することを目指す。

### 1-3. 成果物

- ブラウザで動作するHTML/CSS/JavaScript製のWebアプリ（サーバー不要）
- 本要件定義書および関連ドキュメント群

---

## 2. 利用者・利用環境

### 2-1. 対象ユーザー

開発者自身（個人利用）。日常のタスク・学習・作業の進捗を自分で管理するために使用する。

### 2-2. 利用環境

| 項目         | 内容                                   |
| ------------ | -------------------------------------- |
| デバイス     | PC（メイン）                           |
| ブラウザ     | Google Chrome 120 以降                 |
| JavaScript   | 有効であること                         |
| ネットワーク | インターネット接続不要（ローカル動作） |

---

## 3. 機能要件

カンバンボード上でのカード（タスク）の作成・編集・削除・移動を中心とした機能を提供する。カードにはタイトル・説明文・優先度・期限を設定でき、期限状態を色で視覚的に表示する。また優先度・期限によるソートと、ドラッグ＆ドロップによるフリー並び替えをサポートする。

詳細：[機能要件定義書](functional-spec.md)

---

## 4. 非機能要件

### 4-1. パフォーマンス

| 項目             | 基準                                            |
| ---------------- | ----------------------------------------------- |
| 動作保証カード数 | 合計100枚まで（各列33枚程度）                   |
| 画面反映速度     | カード追加・移動・削除の操作から300ms以内に反映 |
| 初回読み込み     | ファイルを開いてから2秒以内にボードを表示       |

### 4-2. 対応環境

| 項目         | 内容                                        |
| ------------ | ------------------------------------------- |
| 対応ブラウザ | Google Chrome 120 以降                      |
| 非対応環境   | Internet Explorer・Safari・Firefox は対象外 |
| 画面解像度   | 横幅 1280px 以上のデスクトップ画面          |

### 4-3. データ保持

- ブラウザのタブを閉じてもデータが保持される（ローカルストレージ）
- ブラウザのキャッシュクリア・シークレットモードではデータが消える可能性があることを許容する

### 4-4. エラー処理

| エラー状況                     | アプリの挙動                                     |
| ------------------------------ | ------------------------------------------------ |
| タイトル未入力での保存         | 「タイトルを入力してください」と表示し保存しない |
| ローカルストレージ保存失敗     | 「保存に失敗しました」とアラート表示             |
| ローカルストレージ読み込み失敗 | 空のボードで起動し、エラーをコンソールに出力     |

### 4-5. アクセシビリティ

- Esc キーでモーダルを閉じられること
- ボタン・入力欄がキーボードでフォーカス可能であること

## 8. 開発スコープ

### 8-1. MVP（初期リリースで実装する機能）

最初から全機能を目指すのではなく、動くものを早期に完成させることを優先する。

- 3列のカンバンを画面に表示する
- カードの新規作成（タイトルのみ）
- カードの削除
- ボタン操作による列間移動

### 8-2. MVP後に追加する機能

- 説明文・優先度・期限の入力
- カードの編集機能
- ドラッグ＆ドロップによる列間移動
- ローカルストレージへの自動保存

### 8-3. スコープ外（今回は作らないもの）

- ユーザー登録・ログイン機能
- 複数ユーザーでの共有・協同作業
- カラムの追加・削除
- サーバーへのデータ保存

## 10. 前提条件・制約・リスク

### 10-1. 前提条件

- 利用者の端末に Google Chrome 120 以降がインストールされていること
- ブラウザの JavaScript が有効になっていること
- ブラウザのローカルストレージが有効になっていること

### 10-2. 制約条件

| 制約                       | 内容                                                 |
| -------------------------- | ---------------------------------------------------- |
| サーバーなし               | バックエンドを持たないため、複数端末での同期は対象外 |
| ローカルストレージ容量制限 | 通常 5MB が上限。大量データの登録は動作保証対象外    |
| 単一ユーザー               | 認証機能を持たず、複数人での利用は対象外             |

### 10-3. リスクと対策

| リスク                             | 影響度 | 対策                                           |
| ---------------------------------- | ------ | ---------------------------------------------- |
| キャッシュクリアによるデータ消失   | 高     | ユーザーへの注意喚起（アプリ内に説明文を表示） |
| シークレットモードでのデータ非保持 | 中     | 通常モードでの使用を推奨する旨を記載           |
| ブラウザ更新による動作変化         | 低     | 動作確認済みバージョンを本書に明記             |
